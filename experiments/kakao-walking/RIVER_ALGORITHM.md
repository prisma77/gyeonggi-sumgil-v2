# 시간 조건에 따른 하천 왕복 후보 — 2026-10-09

## 범위

명시적인 요청 시간과 보행 속도 가정으로 같은 원본 하천 보행로의 반환점 후보를 최대 3개 만든다.
출발점은 원본 노드 그대로 유지한다. 새 장소나 다른 보행로로 대체하지 않는다.
호수 순환·자연어 해석·AI 연동은 이번 범위에 없다.
원본 입력은 `river-long.probe.json`과 독립 ODbL `river-walkways.osm.json`이다.
특정 장소 ID·좌표를 알고리즘에 하드코딩하지 않는다. 생성 후보와 카카오 응답은 파일로 저장하지 않는다.
OSM 연결·태그는 현재 출입·장벽·통행의 증명이 아니다.

## 후보 생성

`plan_river_candidates.py`는 원본 노드 순서·정확한 좌표·출처를 확인한다.
각 간선의 양방향이 원본 보행망에 있어야 동일 길 왕복 후보를 만든다.
근접 좌표를 연결하거나 source 순서를 바꾸지 않는다. 원본 노드 2–200개를 지원한다.

기존 노드마다 반환점으로 했을 때의 단순 왕복 길이와 예상 시간을 계산한다.
시간은 `원본 왕복 길이 / 명시한 속도`이며 API 시간이나 관측값이 아니다. 휴식은 미포함이다.
입력은 1–120분, 속도 가정 2–6km/h이며 앱에서는 3·4·5km/h를 선택한다.
요청 시간의 ±25% 안에서 예상 시간 차이가 작은 순서로 최대 3개를 제시한다.
±25%는 명시적인 실험 정책이며 제공자 정확도나 사용자 소요 시간을 보장하지 않는다.
후보가 없으면 확보한 구간의 예상 시간 범위를 표시하고 실제 조회를 막는다.

`select_waypoints.py`는 기존 노드에서 경유점 1–5개를 시험해 원본 굴곡 차이를 5m 이내로
유지할 수 있는 **최소 개수**를 선택한다. 반환점은 마지막 경유점으로 반드시 포함한다.
각 개수에서 최대 굴곡 차이를 동적 계획법으로 최소화하고, 동률이면 가장 긴 미선택 원본 구간을 최소화한다.
분석용 현은 경로·지도 선형·API 좌표로 쓰지 않는다. 최대 5개로도 5m 이내에 들지 못하면 후보를 제외한다.
5m는 독립 source 선형의 단순화 실험 기준이며 API 스냅·방문 정확도나 보행 품질을 보장하지 않는다.
첫 구현이 항상 최대 개수를 채우던 문제는 아래 후속 실행에서 수정했다.

`POST /river-candidates`는 원본 profile ID·시간·속도만 받는다. 도보 API 호출은 없다.
원본 감사 후 생성한 후보 최대 3개만 메모리에 유지하고 다시 계산하면 이전 생성 ID를 무효화한다.
실제 조회는 선택한 ID·방식으로 1회 수행한다. Android에서 시간·속도를 바꾸면 이전 후보·경로를 지운다.

## 반환 경로 검증

카카오의 원래 step·좌표를 그대로 표시한다. 누락 구간이나 새 경로선을 만들지 않는다.
`validate_river.py`는 실제 선형을 원본 하천 선형의 누적 길이에 대응시켜 방향을 분석한다.

- 구간 끝점 차이가 1mm보다 크면 연결을 만들지 않고 방향 판정을 보류한다.
- 반환된 선분만 최대 10m 간격으로 분석한다. 분석 표본을 API 입력·경로로 사용하지 않는다.
- 원본 선형 최대 차이 20m, 출발·복귀·반환점 차이 30m를 실험 기준으로 사용한다.
- 평행 구간 등으로 누적 길이 대응이 모호하면 방향 판정을 보류한다.
- 갈 때의 역행과 올 때의 재전진을 누적하며 합계 10m 초과는 불필요한 방향 전환으로 실패한다.
- 정상적인 하천 왕복의 재방문은 불필요 반복으로 처리하지 않는다.
- 분석 표본 10,000개 초과 또는 검사 기준에 비해 짧은 구간은 보류한다.
- `PASS_GEOMETRY_ONLY`는 기하 모델만 통과한 것이다. 현재 통행을 승인하지 않는다.

실제 API 예상 시간도 요청과 따로 비교한다. ±25% 초과는 `TARGET_DURATION_MISMATCH`다.
원본 예상과 API 예상이 다르면 둘 다 표시한다. 모든 응답의 추천 상태는 `NOT_ACCEPTED`다.

동일한 anchor를 여러 바퀴 돌아 거리만 늘리는 방식은 사용하지 않는다.
순서 감사는 증가하는 원본 인덱스·반환점·정확한 역순 복귀만 허용한다.

최신 첫 후보의 원본 선택 인덱스는 outbound `[27, 46, 57]`, 전체 `[27, 46, 57, 46, 27]`이다.
굴곡 요약 오차 25.6m로 기존 5m 요약 기준을 충족하지 못한다는 사실을 화면에 표시한다.
직선 요약선은 실제 경로가 아니므로 이 시험 입력을 승인된 경로로 취급하지 않는다.
5m 기준을 완화해 통과로 바꾸지 않았으며 실제 응답의 원본 보행로 20m·역행 10m·
방문 30m·구간 연결 1mm 검사 기준은 그대로 유지했다.
지도는 같은 좌표의 재방문 anchor를 `1·5`, `2·4`로 묶고 실제 반환점을 `R`로 표시한다.
마커나 원본 경로 좌표는 이동하지 않았다.

두 번째 실제 시험은 동일한 원본 길이·출발·반환점·SHORTEST에서 양방향 경유점을 사용했다.
UTC `2026-10-09T03:52:15.175592+00:00`, HTTP 200 / OK,
**2,664m·2,508초(41분 48초)**, 19개 step이다.
중복 anchor 요청은 이 실제 응답에서 OK였지만 모든 구간의 지원으로 일반화하지 않는다.
경유점 차이 6.1/1.0/0.5/1.0/6.1m, 순서 `PASS_WITHIN_30M`, 거리·시간 조건은 통과했다.
첫 시험보다 255m·161초 줄었다. 보고 거리와 원본 차이는 246.2m,
반환 선형과 원본 차이는 204.0m로 여전히 거리 대조 기준을 초과한다.
원본 선형 근접 검사 실패와 step 끝점 차이도 남았다.
방향 검사는 연결 조건에서 보류되어 최대 corridor 차이·역행 수치를 측정하지 않았다.
동일 선분 반복 하한 1,311.6m는 필요한 왕복도 포함하며 불필요 반복량이 아니다.

휴대폰에 최종 APK를 설치하고 지도에서 S·1·5·2·4·R과 붉은 실패 경로,
2,664m 결과를 메모리 캡처로 확인했다. API 응답·좌표·캡처는 파일로 저장하지 않았다.
**거리 목표는 충족했지만 코스 품질은 계속 `NOT_ACCEPTED`다.**
남은 원본/API 불일치 구간과 끝점 차이를 대조해야 하며 현재 통행은 별도 확인 대상이다.
호수 순환·자유로운 장소 탐색·AI 모델 변경은 이번 범위에 포함하지 않았다.

이번 거리 단계 실제 도보 호출은 **2회**다. 이전 3회와 합해 연속 하천 후보 실험은 5회이며,

## 후보 다양화·입력 모호성·탈락 우선 비교 — 후속 알고리즘 작업

### 채택한 변경

- 거리 조건이 있는 후보의 반환점은 원본 경로 누적 거리로 최소 75m 떨어지도록 고른다.
  직선 거리가 아니라 동일한 원본 경로상의 간격이다. 3개를 억지로 채우지 않는다.
  이번 원본은 편도 1,208.9m와 1,092.8m의 두 후보를 공급하며 출발점은 유지한다.
- `select_network_anchors.py`는 원본 양방향 그래프의 갈림길과
  highway/bridge/tunnel/layer 분류 변화 주변을 중간 경유점 선택에서 제외한다.
  30m 원본 누적 거리의 입력 선별 정책이며 현장 안전이나 API 링크 선택의 보장은 아니다.
  출발·반환점을 다른 노드로 이동시키지 않고, 끝점의 원본망 모호성은 별도 표시한다.
- `select_waypoints.py`의 제한된 입력 노드 선택에서도 오차는 **모든 원본 경로 점**으로 계산한다.
  제외된 입력 노드를 원본 보행로에서 삭제하여 굴곡·품질 차이를 숨기지 않는다.
  갈 때 최대 3개, 복귀 anchor 역순을 포함한 전체 요청 최대 5개는 유지한다.
- `validate_river.py`는 step 연결이 보류되어도 각 실제 step의 보행로 이탈·반환점 검사는 수행한다.
  정확한 끝점 차이(소수점 6자리), 보류 구간 수, 이탈에 대응하는 원본 선분 인덱스를 반환한다.
  전체 진행 방향 계산은 연결 조건을 만족해야만 수행한다. 좌표나 경로선을 연결·수정하지 않는다.
- `compare_candidates.py`는 HTTP/응답·선형·왕복·거리·시간·source 대조 검사를 먼저 확인한다.
  실패는 `REJECTED`, 미확인은 `REVIEW_REQUIRED`이며 둘 다 비교 점수가 없다.
  통과한 선형 후보가 있을 때만 API 시간 적합도 → 자료 간 선형 길이 차이 순으로 비교한다.
  조용함·녹지·대기질·통행 상태를 추정해서 점수를 만들지 않는다.
  통과 후보가 없으면 `NO_VALIDATED_CANDIDATE`, best ID는 null이다.
  선형 통과도 현재 통행·최종 추천 승인을 뜻하지 않는다.
- bridge의 비교 내역은 현재 source 후보 생성 세션·동일 route mode에 한정된다.
  판정·수치만 RAM에서 보관하고 source 후보를 다시 만들면 초기화한다.
  provider 응답·경로·좌표·지도 캡처를 저장하지 않는다. 자동 추가 호출도 없다.

75m 후보 간격, 30m 입력 선별은 실험 정책이다. 기존 실제 경로 검사 기준
(원본 corridor 20m, 역행 누적 10m, 방문 30m, step 연결 1mm)은 변경하지 않았다.
단일 시험의 API 결과를 맞추려고 장소별 좌표·경로·제외 노드를 하드코딩하지 않았다.

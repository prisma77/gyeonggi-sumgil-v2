# 호수 순환 판정 근거 개선 — 2026-10-09

## 완료 범위

선택 장소 보행망 연결 이후의 작은 단계다. 실제 응답을 보정하지 않고 보류 근거를 구체화했다.
호수 순환 코스 자체의 해결이나 추천 승인을 의미하지 않는다.

- API step 끝점의 최대 차이와 어느 구간 사이인지 표시한다. 1mm 분석 기준을 유지하며 끊긴 경로를 잇지 않는다.
- OSM 수역과 API 선형을 최대 10m 간격의 검사점으로 대조한다.
  수역 내부 검사점 수, 경계 안쪽 최대 거리, 해당 step 번호를 표시한다.
  표본 검사이며 모든 좁은 수역 교차를 찾아낸다는 보장은 없다. OSM 경계는 현장 관측이나 절대 기준이 아니다.
- 원본에서 접근 금지가 아닌 보행 way의 bridge 태그를 대조한다. 검사점에서 5m 이내인지도 표시한다.
  이는 출처 간 위치 비교 정책이다. 교량 태그 근처에 있어도 실제 교량 통행·수역 경계 정확도를 승인하지 않는다.
  원본 없음과 원본에 근처 교량 없음은 구분한다.
- 경계와 교량 edge 합계 5000개 또는 표본 분석 연산 200만 초과 시 평가 못함으로 반환한다.
  부분 분석을 완료된 검사처럼 합산하지 않는다.
- 모든 호수에 무조건 붙던 반복 검토 경고를 실제 동일 선분 재방문 또는 비단순 순환 발견 시에만 붙인다.
  완전 연결·단순·전체 수역 포함 조건을 충족한 시험 선형은 선형 검사만 통과한다.
  현재 통행 UNVERIFIED와 서버 추천 NOT_ACCEPTED는 그대로다.
- 선택 장소 화면의 입력 설명은 원본 후보 생성과 접근 구간 제외를 설명한다.
  과거 별도 비교 시험의 “출발점이 달라짐” 문구를 사용하지 않는다.

## 실제 API 시험

미사호수공원은 카카오 검색의 실제 이름·주소를 대조했다. 이름 없는 OSM 수역은 지도에서 직접 대조한 후
실험 입력으로 선택했다. 앱 후보 선택·OSM 경계 확인 흐름을 건너뛰는 일반 알고리즘 하드코딩은 없다.

| --- | --- | --- |

두 실행은 같은 장소·수역·후보 생성 정책을 사용했지만 원본을 각각 새로 확보했다.
고정 응답을 재생한 통제 실험이 아니므로 모든 차이를 route_mode 때문이라고 단정하지 않는다.
큰길 우선으로 바꾸는 것만으로 정상 순환을 확보하지 못했다.

Xiaomi 응답의 15번 step에 OSM 수역 내부 검사점 1개가 있었다. 경계 안쪽 최대 3.846m이고
원본 보행 교량 5m 이내 검사점도 1개였다. 이를 실제 수중 보행이나 교량 통행 확인으로 해석하지 않는다.
순환은 끊긴 step 때문에 전체 수역 포함 여부를 아직 판정할 수 없고,
27.1m 재방문은 원본/API의 접근 가지·우회인지 추가 검토가 필요하다.

[카카오 공식 도보 API 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api)의 step별 path.points와
properties를 확인했다. 이번에 확인한 문서에서 0.410m 차이를 승인하거나 누락 구간을 자동 보간할 근거를 확보하지 못했다.
특정 제공자 문제로 원인을 확정하지 않는다.

이번 단계의 실제 호출 합계는 카카오 장소 4회·OSM 2회·도보 2회·Gemini 0회다.
PC 진단은 1·1·1회, 실기기 세션은 3·1·1회다. 이전 단계 호출 합계와 구분한다.
허용된 실기기 GPS는 카카오 주변 검색에만 사용했고 Gemini에 보내지 않았다.
새 원본·API 경로 응답·실기기 지도 캡처는 파일로 저장하지 않았다.

## 실행 검증과 한계

- Python 경로 검사 126개, 장소·서버·선택 보행망 검사 41개 통과.
  단순 완전 순환의 선형 통과, 반복 순환의 보류, 원본/API 불변,
  작은 연결 차이의 보류, 교량 태그가 있어도 미승인, 원본 누락 및 분석 한도의 보류를 포함한다.
- Kotlin 단위 테스트 52개 통과, 유료 Gemini 수동 시험 2개 건너뜀. APK build·lint 성공(0 errors, 11 warnings).
- Xiaomi에서 실제 검색→수역 지도 대조→원본 후보→BROAD_FIRST 요청→붉은 실패 경로→상세 수치를 확인했다.
  연결 차이 0.410m, 13→14 구간, 수역 검사점과 교량 대조 설명이 화면에 표시됐다.
  크래시 버퍼 FATAL EXCEPTION 0건. 마지막 설명 문구 수정 이후에도 APK build·lint를 다시 통과했다.
  최종 APK를 실기기와 Android Studio 에뮬레이터에 설치·실행했다. 에뮬레이터에는 이전 실행의 크래시 기록이
  남아 있었으나 현재 앱 PID에는 해당 기록이 없고, 경로 탭에서 x86 SDK 지원 제한 안내를 확인했다.
  에뮬레이터에서 실제 카카오 지도 품질을 검증했다는 의미는 아니다.
  최종 설치 이후 유료 경로를 재조회하지 않았다. 실제 지도·진단 표시 검증은 문구 수정 직전 APK에서 수행했다.

해결되지 않은 항목은 step 연결의 의미 확인, 순환과 접근 가지의 분리 판정,
교량·수역 경계 및 현재 출입·통행 확인이다. 임의 connector·거리 채우기·교량 태그만으로 승인하는 처리는 추가하지 않았다.

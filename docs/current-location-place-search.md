# 현재 위치 기준 장소 탐색 — 2026-10-09

이 문서는 장소 탐색 기능을 처음 연결했을 때의 범위·검증 기록이다.
후속 단계에서 선택 장소의 보행망 확보와 실제 경로 조회를 연결했다. 최신 범위는 [선택 장소 경로 기록](selected-place-route.md)을 참조한다.

## 이번 기능

경로 탭의 `산책 장소 찾기`에서 장소명·지역을 비우고 `현재 위치 주변 찾기`를 누르면,
Android 위치 제공자의 실제 측정 좌표를 기준으로 3km 주변의 공원·호수·하천 후보를 검색한다.
장소명을 입력하면 입력한 검색어를 유지하며 현재 위치는 거리 정렬의 기준으로만 사용한다.
명시한 장소에는 3km 반경 제한을 적용하지 않아 멀리 지정한 장소를 가까운 다른 장소로 바꾸지 않는다.

- 위치 권한이 없으면 주변 검색을 위한 권한 요청. 거절하면 장소·지역을 입력하는 방법 안내.
- 위치는 측정 후 2분 이내, 보고 정확도 150m 이내일 때만 사용한다. 이는 이번 검색 정책이며 위치 정확도의 보장이 아니다.
- 신선한 캐시가 없으면 GPS·network 제공자를 각각 최대 6초 기다린다. 취소 시 위치 요청도 해제한다.
- 측정소·기존 코스 중심·기본 지도 좌표로 사용자 위치를 대체하지 않는다.
- 이름 검색은 위치가 없어도 가능하되, 위치 미확인과 주소 확인 필요를 표시한다.
- 반환 분류로 공원·호수·하천·산책로·수목원·생태공원을 추리고 주차장·카페·정류장은 제외한다.
- 거리 정렬 후보 최대 5개, 표시 범위 한계·검색 시각·주소·분류 표시. 자동 페이지 확장과 재시도 없음.
- 검색 실패 또는 후보 없음에서는 다른 검색어·현재 위치로 재요청하지 않는다.
- 후보를 직접 선택해야 장소가 확정된다. 선택 시 목록을 접고, 원본 POI 좌표로 지도 중심만 이동한다.
- 확인한 검색 장소가 있으면 기존 고정 시험 입력과 경로 조회를 막는다. 다른 시험 장소로 대체하지 않는다.
- 검색 거리는 실제 보행 거리와 다르다. 장소 좌표는 검증된 출입구·보행 지점이 아니다.

**이번 단계는 장소 탐색·확인이다. 자연어 전체 해석이나 선택한 새 장소의 자동 보행망 확보·경로 생성은 아직 연결하지 않았다.**
입력칸은 장소명·지역용이며, 거리·시간·한바퀴 조건을 이 검색 API에 맡기지 않는다.
선택 장소를 확인해도 추천 승인으로 표시하지 않는다.

## 교체 경계 및 전송

Android `PlaceSearchGateway`와 `SearchLocation`/`PlaceCandidate` 모델을 분리했다.
현재 구현 `LocalPlaceSearchGateway`는 기존 PC 검증 서버의 `/places`를 사용한다.
출시용 원격 서버와 인증 구성은 아직 없으며 이 루프백 연결을 운영 서비스로 설명하지 않는다.
REST 키는 PC의 `local.properties`에서만 읽고 Android APK에 추가하지 않았다.

앱→PC: 검색어와 선택적으로 현재 위도·경도, 정확도, 위치 나이.
PC→카카오: 검색어, 현재 위도·경도, 거리 정렬, 주변 검색이면 반경 3000m.
위치 정확도·나이는 PC에서 검사하며 카카오 검색 파라미터로 보내지 않는다.
Gemini 호출이나 위치 전송은 없다. 요청·응답·현재 좌표는 파일/DB/원문 로그에 저장하지 않는다.

공식 기준:

- [카카오 장소 검색 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api#search-by-keyword):
  키워드, x/y, 반경, 거리 정렬, 응답 분류·주소·좌표·거리.
- [Android 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions),
  [LocationManager](https://developer.android.com/reference/android/location/LocationManager):
  사용자 권한과 foreground 위치 요청·취소를 반영했다.

## 실제 검색에서 발견한 문제와 변경

공개 OSM 오산종합운동장 노드를 시험 기준점으로 쓰고 `부산 중앙공원`을 조회했다.
제공자 원본 결과에 경기 부천 후보 및 다른 이름의 광장도 섞여 반환됐다.
키워드 검색 결과가 요청 장소와 정확히 일치한다고 가정하지 않는다.

요청의 공백으로 구분된 명시 시·도 토큰과 반환 지번 주소의 시·도를 비교하고,
명시한 공원·호수 등의 이름 단어를 후보 장소명과 대조하는 검사를 추가했다.
재조회에서 부산 주소와 중앙공원 이름을 유지하는 후보만 표시됐으며, 단일 후보를 자동 채택하지 않았다.

현재 토큰 검사는 제한된 규칙이다. `광주`만 쓰면 광역시와 경기 광주시를 자동 구분하지 않으며,
붙여쓴 지역명·상세 시군구·자연어 문장의 모든 지역 조건을 추출하는 기능은 아니다.
후보 주소 확인이 필요하고 이 규칙만으로 지역·장소 일치를 최종 승인하지 않는다.

## 실행·검증 결과

- Kotlin 단위 테스트 52개 통과, 수동 유료 Gemini 실험 2개 건너뜀.
  새 위치 검사 6개: 위치 없음·오래됨·부정확함·비정상 좌표 거절, 명시 장소 검색 보존.
- Python bridge·장소 검색 테스트 27개 통과. 지역 불일치·주차장·이름 교체·동명 후보·예산 부족·HTTP 실패 검사 포함.
- 최신 `testDebugUnitTest assembleDebug lintDebug` 성공. lint 오류 0개, 기존 경고 11개.
  처음 lint에서 위치 권한 취소 처리를 지적해 명시적 SecurityException 처리를 추가한 뒤 통과했다.
- Android Studio emulator-5554에서 공개 OSM 시험 노드를 **모의 위치**로 사용했다.
  실제 사용자 위치가 아니며, 원본 지점 인근 오산천과 공원 후보를 실제 검색 API에서 확인했다.
- 최신 APK에서 위치 정확도 약 5m·측정 나이, 최대 5개 표시, 직접 후보 선택과 선택 후 목록 접기 확인.
- 최신 APK에서 없는 이름 `SumgilNoSuchPark987654321` 조회 후 후보 없음·대체 없음 안내 확인.
- 이름 검색의 동명 후보와 멀리 지정한 지역 보존은 PC 루프백→실제 카카오 응답으로 별도 확인했다.
- Gemini·도보 API 호출은 이번 기능 시험에 없다. 장소 검색은 별도 계수이며 과금·계정 전체 쿼터는 콘솔 확인 대상이다.
- 실제 장소 검색 총 13회: 첫 에뮬레이터 주변 검색 3회, 중앙공원/부산 검색 2회,
  없는 이름 검색 1회, 수정 후 부산 재검색 1회, 최신 에뮬레이터 주변 검색 3회,
  사용자 승인 후 실기기 주변 검색 3회.

## 실기기 상태

Xiaomi에 같은 최신 APK를 설치하고 실제 현재 위치로 장소 탐색을 검증했다.
처음에는 실제 좌표 전송에 대한 명시적 승인이 없다는 자동 승인 심사로 중단했다.
사용자가 위도·경도와 검색어를 PC 검증 서버를 거쳐 카카오 장소 검색 API로 전송하는 시험을
명시적으로 허용한 뒤 실행했다. 실제 좌표·원본 검색 응답·지도 캡처는 파일에 저장하지 않았다.

- 최초 조회는 기존 서버의 남은 검색 한도 2회가 주변 검색에 필요한 3회보다 적어 중단됐다.
  카카오 호출 없이 실패 안내를 표시했고 자동 재시도나 일부 결과 표시는 없었다.
- 기존 서버를 종료하고 검색 한도 3회의 서버 하나로 다시 시작한 뒤 사용자가 승인한 조회를 실행했다.
- 실제 위치 기준 후보 5개와 위치 품질·KST 검색 시각·거리 및 목록 한계 안내를 확인했다.
  위치 확인 당시 보고 정확도 약 100m, 측정 후 81초였다. 이는 측정값이며 정확성 보장이 아니다.
- 후보를 직접 선택하면 목록이 접히고 선택한 장소로 지도 중심이 이동했다.
  출입구·보행 지점 미검증과 새 장소의 경로 생성 미연결 안내를 확인했다.
- 선택 후 기존 시험 입력과 실제 경로 조회 버튼의 클릭 가능한 부모 노드가 비활성 상태임을 확인했다.
  선택한 새 장소를 기존 시험 코스로 바꾸지 않았다.
- 후보 선택 후 서버 계수는 검색 3/3회, 도보 0/1회로 유지됐다. 이번 실기기 시험에 Gemini 호출은 없다.
- 앱 프로세스의 AndroidRuntime 로그에서 FATAL EXCEPTION 0건을 확인했다.

장소 탐색·직접 선택·지도 중심 이동은 실기기에서 확인했지만,
새 장소의 실제 보행 경로 생성과 추천 품질은 이번 단계의 검증 범위가 아니다.

## 사용

PC 검증 서버와 USB 연결이 필요하다. 저장소 루트에서:

```powershell
python -B experiments/android-route-review/bridge.py --catalog experiments/android-route-review/unseen-sites.catalog.json --max-calls 1 --max-search-calls 6
adb reverse tcp:8769 tcp:8769
```

주변 버튼 한 번은 공원·호수·하천 키워드로 **검색 API 3회**,
이름 검색 한 번은 **검색 API 1회**다. 남은 검색 예산이 부족하면 일부만 조회해 성공으로 표시하지 않는다.
서버 시작·후보 선택·지도 중심 이동은 검색 또는 도보 조회를 추가로 호출하지 않는다.
도보 한도와 검색 한도는 독립적이며, 선택한 검색 장소의 보행 경로 생성은 다음 단계다.

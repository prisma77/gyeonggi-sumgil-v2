# 처음 시험하는 장소의 실제 경로 검증 — 2026-10-09

기존 탄천·원천호수·신대호수·미사호수공원을 제외하고 **의왕 백운호수와 오산천**을 처음 시험했다.
AI 해석 예시에도 사용하지 않았던 두 장소다. 실제 경로 호출 전 기준을 정하고,
기존 후보 계산과 검사 코드를 그대로 사용했다. 장소별 운영 알고리즘이나 통과 예외를 추가하지 않았다.

## 장소 및 독립 자료 확인

- 카카오 장소 검색 2회에서 백운호수의 호수 분류·의왕 지역, 오산천의 하천 분류·오산 지역을 확인했다.
  주차장·음식마을은 호수 후보로 채택하지 않았다. 오산천은 여러 구간 검색 결과가 있으므로
  이번 시험 구역을 공개 OSM의 오산종합운동장 인근으로 명시했다. 사용자 위치로 대체하지 않았다.
- [의왕시 백운호수 안내](https://www.uiwang.go.kr/culture/UWTOURSEE0106) 및
  [백운호수 데크 산책로 안내](https://www.uiwang.go.kr/culture/UWTOURSEROAD002)에서 대상과 시설 안내를 확인했다.
  안내 이미지나 관광 소개 거리를 앱 코스·실제 API 거리로 사용하지 않았다.
- `queries/unseen-targets.overpass`: 이름으로 실제 수역과 하천 원본을 발견했다.
  백운호수 버스정류장 2개도 반환됐으나 수역은 `way/37221016`, `natural=water`로 구분했다.
- 백운호수: 수역 경계에서 150m 여유를 둔 OSM Map API 자료. 수집 `2026-10-09T09:23:01.102062+00:00`.
  원본 보행망 32개 way, 454개 보행 node. 요청점은 원본 데크·교량 태그가 있는 보행 노드다.
  기존 순환 탐색은 전체 원본 수역을 감싸는 보행 순환을 찾지 못했다. 연결선을 만들어 보완하지 않았다.
- 오산천: OSM `way/468999194` 오산종합운동장 형상 주변 1500m Map API 자료.
  수집 `2026-10-09T09:24:00.657806+00:00`.
  `way/1087492729`, `highway=footway`의 연결된 60개 node, 편도 원본 2182.7m를 선택했다.
  운동장 형상 중심에 가까운 쪽의 원본 끝점에서 출발한다. 운동장 중심과 약 260m 차이이며,
  운동장 내부 또는 운동장 문을 출발점으로 주장하지 않는다.
- 두 입력 모두 원본 노드 좌표·태그와 일치하고 방향 보행 그래프로 순서·복귀가 연결됐다.
  원본 연결 확인과 현재 출입·통행 확인은 별도다. 장벽·조건부 출입·현장 상황은 미확인이다.

저장 자료는 © OpenStreetMap contributors / [ODbL 1.0](https://www.openstreetmap.org/copyright) 원본 추출이다.
보행 허용 way 전체, 수역·하천 way, 해당 원본 node 및 반환된 barrier node를 남겼다.
추출 전후 보행 좌표·방향 연결·태그가 동일하고 백운호수 수역 경계가 동일함을 비교했다.
다른 시설과 relation은 제외했으며 이번 대상 호수는 단일 water way다.
원본 수집 시각은 현장 관측 또는 각 구간 수정 시각이 아니다.

## 실제 Android 조회 결과

최신 설치된 debug APK를 Xiaomi 21121210G / arm64-v8a에서 실행했다.
앱 코드를 변경하지 않고 별도 `unseen-sites.catalog.json`으로 새 시험 입력을 제공했다.
카카오 지도 인증, 새 장소 선택, 원본 후보 계산, 실제 선형·요청점·검사 결과 표시를 확인했다.
새 서버 도보 호출 상한 2회, 수동 조회 각각 1회, 완료 후 2/2를 확인했다.
Gemini API 호출이나 집↔공원 접근 경로 조회는 이번 시험에 없다.

| 장소·조건 | 실제 카카오 도보 응답 | 판정 |
| --- | --- | --- |
| 오산천 2~3km 왕복, 38분·4km/h 가정, 후보 1 | 2564m / 2290초(38분 10초), 6구간 | 거리·시간·경유점 순서·반환점·왕복 방향·원본 보행로 일치 검사 통과. 현재 통행 미확인, 추천 미승인 |
| 백운호수 호숫가 요청점, 동일 출발·도착 | 3266m / 3079초(51분 19초), 14구간 | 방문·순서 통과. 전체 수역 포위 조건 실패, 순환 추천 미승인 |

실제 조회 시각은 각각 `2026-10-09T09:28:44.353037+00:00`(18:28 KST),
`2026-10-09T09:29:48.419255+00:00`(18:29 KST)다.
HTTP 200 / OK이며 요금·계정 전체 사용량·쿼터는 콘솔 확인 대상이다.
원본 API 응답·반환 좌표·지도 캡처는 파일로 저장하지 않고 메모리에서만 검사했다.

### 오산천 세부 결과

- 같은 원본 길 왕복 후보는 2549.6m / 가정 속도 예상 38.24분이다.
  기존 알고리즘은 원본 예상 왕복 2549.6m, 2367.8m, 2714.3m 후보를 계산했다. 첫 후보만 API 조회했다.
- 경유점 5개는 `A → B → R → B → A` 순서다. 지도에서 같은 좌표의 왕복 표식은 `1·5`, `2·4`로 합쳐 보였다.
  표식을 임의 좌표나 선 위의 보기 좋은 점으로 옮기지 않았다.
- 경유점 차이 0.1 / 2.2 / 0.4 / 2.2 / 0.1m. 반환점 차이 0.4m, 원본 보행로 최대 차이 2.5m.
- 응답 구간 끝점 최대 차이 0m, 보류 구간 0개, 갈 때·올 때 방향 역행 진단 0m.
- API 거리와 원본 왕복 차이 14.4m, 반환 선형 길이와 원본 차이 1.0m.
- 동일 선분 반복 하한 1275.3m는 의도한 왕복을 포함한다. 불필요한 반복 거리로 판단하지 않는다.
- 이번 단회 응답은 이 후보의 선형 검사 성공이며, 오산천의 모든 구간이나 모든 제공자 응답의 성공은 아니다.

### 백운호수 세부 결과

- 경유점 차이 0.7 / 0.6 / 2.3 / 1.2 / 0.7m. 30m 방문 기준과 순서 검사 통과.
- 정확히 같은 선분 반복 진단은 0m다. 다른 좌표 분할의 반복은 이 수치에 포함하지 않는다.
- 전체 수역 포위 검사는 실패했고, 수역 통과 의심 구간의 교량 확인 및 순환 구조 검토가 남았다.
- 원본에는 데크·교량 태그가 있고 일부 요청점이 원본 수역 안에 놓인다.
  **이 결과만으로 실제 둘레길이 없거나 API가 잘못됐다고 단정하지 않는다.**
  실제 데크 형상·수역 경계 자료의 정합성과 사용자의 한바퀴 의미를 대조해야 한다.
- 거리 3.266km 또는 출발점 복귀만으로 한바퀴를 승인하지 않았다.
  이번 호수 시험은 거리 목표를 따로 입력하지 않았으므로 '3km 조건 통과'라고 기록하지 않는다.

## 검증 및 다시 실행

- 기존 Python 경로 검사 117개 + 로컬 bridge 검사 15개 = 132개 통과.
  bridge의 첫 샌드박스 실행에서는 로컬 소켓 권한 오류가 있었고 네트워크 권한을 갖춘 재실행에서 통과했다.
- 신규 원본 입력 감사 2건 통과. 추출 전후 원본 보행망과 호수 경계 동일성 확인.
- 휴대폰 앱 시작·지도 표시 정상, 해당 프로세스 FATAL EXCEPTION 없음.
- 이번 변경은 시험 자료·카탈로그·기록이다. 새 Android 코드 변경이나 APK 재빌드는 없다.
  소프트웨어 검사 성공과 실제 코스 검사 결과를 구분한다.
- 커밋·푸시는 사용자가 수행한다.

저장소 루트에서 실행한다. 서버 시작 자체는 도보 API를 호출하지 않는다.
앱에서 버튼을 누르면 새 유료 조회가 발생하므로 기존 결과를 확인하려고 반복 호출하지 않는다.

```powershell
python -B experiments/android-route-review/bridge.py --catalog experiments/android-route-review/unseen-sites.catalog.json --max-calls 2
```

같은 포트의 기존 시험 서버는 먼저 종료한다. USB 연결 뒤
`adb reverse tcp:8769 tcp:8769`를 설정하고 앱을 다시 열어 `경로`에서 새 입력을 선택한다.
오산천은 `시간에 맞는 반환점 후보 계산` → 후보 선택 → 실제 경로 조회 순서다.
백운호수는 호숫가 시험 입력을 명시적으로 선택한다. 다른 장소로 자동 대체하지 않는다.

다음 개선에서는 백운호수의 데크와 수역 경계 사례를 분석하되 통과 기준을 느슨하게 바꿔 성공시키지 않는다.
오산천 성공 사례도 함께 유지해 새 검증 규칙이 왕복 경로를 잘못 거절하는지 비교한다.
